01 / The rule set

Four explicit signals.
A bounded review.

The analyzer stays deliberately narrow: Compose configuration risks that can be evaluated locally and explained with evidence.

CHECK / 01
PRIVILEGED_CONTAINER

Privileged container mode

Flags a service using privileged: true, a direct elevation of container capabilities.

CHECK / 02
WRITABLE_HOST_BIND

Writable local bind

Identifies a local host directory mounted into a service with write access.

CHECK / 03
DANGEROUS_CAPABILITY

High-risk capabilities

Checks explicit additions such as ALL, NET_ADMIN, SYS_ADMIN, and SYS_PTRACE.

CHECK / 04
EXPOSED_SERVICE_PORT

Published service ports

Reports explicit host-published ports, while leaving reachability and runtime state outside the claim.

02 / The correlation

One join.
No overreach.

When privileged mode and a writable host bind affect the same service, SynapseAudit emits one bounded attack-path explanation. It is static analysis, not an exploit or generalized graph discovery.

03 / The boundary

Local by design.

Every result comes from the configuration in front of you. The analyzer does not turn a static finding into a claim about a running environment.

01

Reads YAML locally. Uses safe parsing and evaluates the repository-owned fixture configurations.

02

No services started. No images, commands, containers, or Docker operations are executed.

03

No external surface. The server binds to loopback, contacts no external systems, and does not access host resources or the Docker socket.

04

Configuration-only claims. Findings do not prove internet reachability, firewall exposure, routing, proxy access, or that a service is running.
